# Upgrade notes: Phase 11 (promotions and returns)

## Required actions

1. Run `php artisan migrate`. It creates `promotions`, `coupons`, `promotion_redemptions`, `return_requests` and `return_request_lines`, and adds `carts.coupon_code` and `order_items.discount_amount`.
2. Rebuild non-default themes (`npm run build:theme -- <id>`, then activate or publish again). The cart and the order page have new parts: the coupon box and returns. Themes ship prebuilt bundles, so they only get core changes when rebuilt.

## Behaviour changes

- **Promotions:** new admin group *Marketing → Promotions* with the permission **marketing.promotions.manage**. See [promotions](../marketing/promotions.md).
- **Coupon box:** the cart has a coupon box. The Store API has `POST`/`DELETE /cart/coupon`, and the Admin API has `/promotions`.
- **Returns:** new admin page *Sales → Returns* with the permission **sales.returns.manage**, a return form on the order page, and new settings under *Returns* and *Emails → Return request updates*. See [returns](../ecommerce/returns.md).
- **Discounts in orders:** discounts are recorded per order line. Tax is charged on the discounted amount, and refunds return what was paid for the units. Orders placed before this update have no discounts, so their numbers are unchanged.

## For developers

- **Per-line discounts:** `CartTotals::discount()`, `discountOn()` and `discounts()` record discounts per line (`item:<variant id>` or `shipping`). `ApplyTax` taxes the amounts after discounts. A plugin stage that gives discounts should record them the same way.
- **Totals context:** `ShoppingCartService::totals()` fills in `coupon_code` and `user` in the context. Checkout also passes `email`.
- **`OrderPlacing` event:** a new event fired inside the checkout transaction, before commit. A listener may throw `CheckoutException` to abort the order. Promotion redemptions use it.
- **Plugin extension points:** plugins can register promotion condition and action types (`PromotionRegistry`).
