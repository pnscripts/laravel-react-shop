# Upgrade notes: Phase 10 (APIs)

## Required actions

1. Run `composer install`, which adds `laravel/sanctum`, and then `php artisan migrate`, which creates `personal_access_tokens`.
2. If you deploy with a route cache, rebuild it with `php artisan route:cache`. The API routes are registered by the new core module `PnShop\Api`.

## Behaviour changes

- **New APIs:** see [docs/api](../api/README.md).
  - The **Store API** lives at `/api/store/v1` and is public, with optional customer tokens.
  - The **Admin API** lives at `/api/admin/v1` and needs staff tokens.
- **New admin page:** System → API tokens, available to every staff member for their own tokens.
- **Rate limits:** two new limiters, `store-api` and `admin-api`. Configure them with `PNSHOP_STORE_API_RATE_LIMIT` and `PNSHOP_ADMIN_API_RATE_LIMIT`.
- **No change for the storefront:**
  - The storefront still uses sessions; API requests never read the session.
  - The shop's product filters, product page data and checkout validation now come from shared classes (`ProductBrowser`, `ProductDetailPresenter`, `CheckoutRules`). Their output is unchanged.

## For developers

- **Sanctum config:** `config/sanctum.php` sets `guard` to `[]` so that tokens are the only way into the APIs. The new guards `store-api` and `admin-api` (Sanctum driver) accept only customer or staff tokens respectively.
- **Token-limited permissions:** `AdminUser::hasPermissionTo()` and the administrator `Gate::before` respect the abilities of the token in use. A policy that calls `$admin->can('…')` is therefore automatically limited by the token.
- **Stateless carts:** `CartRepository::useStatelessToken()` lets a request work on a guest cart named by a header instead of the session and cookie.
- **Errors:** `PnShop\Api\Http\Problem` renders problem+json for `api/*`. Map new domain exceptions there.
- **OpenAPI:** `dedoc/scramble` is a dev dependency. Regenerate the documents with `composer api-docs` against a migrated database.
