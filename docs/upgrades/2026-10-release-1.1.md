# Upgrade notes: 1.1 (the core as a Composer package)

The core of PN Shop is now the Composer package `pnscripts/pn-shop-core`, and a shop is a thin `pnscripts/pn-shop` project. The database does not change. The step-by-step guide is in [Updating → From 1.0 to 1.1](../installation/updating.md#from-10-to-11).

## Required actions

1. **Project files:** take the 1.1 versions of `bootstrap/app.php`, `bootstrap/providers.php`, `app/Models/User.php`, `routes/web.php`, `config/pnshop.php` and `composer.json`, then re-apply your own changes to them.
2. **Old files:** run `php artisan pnshop:migrate-to-package`. It sets aside the files that 1.0 kept in the project (`core/`, `app/Http`, `resources/js`, `resources/css`, the base migrations and seeders, `lang/bg.json`, `themes/pnshop/default`) and lists the ones you had changed.
3. **Themes:** rebuild non-default themes (`npm run build:theme -- <vendor/name>`).

## Behaviour changes

- **Updates:** `composer update pnscripts/pn-shop-core --with-all-dependencies`, then `php artisan pnshop:update`.
  - Composer publishes the core's prebuilt storefront to `public/vendor/pnshop/build`.
  - `pnshop:update` refuses to run when the database is from a newer core, or when `composer.lock` and `vendor/` disagree about the core.
- **Storefront assets:** the default storefront loads the core's prebuilt bundle (`public/vendor/pnshop/build`). A project's own build in `public/build` (`npm run dev` / `npm run build`) takes precedence when present.
- **`composer create-project`:** it no longer runs `migrate` after creating the project. `pnshop:install` creates the tables.
- **Built-in theme:** only the core's own theme can be `"builtin": true`. A `themes/pnshop/default` folder left from 1.0 is ignored.

## For developers

- **Moved code:**

  | 1.0 | 1.1 |
  |---|---|
  | `core/<Module>` | `src/<Module>` in the package (`PnShop\<Module>`, unchanged) |
  | `App\Http\Controllers`, `App\Http\Middleware`, `App\Http\Requests` | `PnShop\Storefront\Http\…` |
  | `Database\Seeders` | `PnShop\Database\Seeders` |
  | `Database\Factories\UserFactory` | `PnShop\Customer\Factories\UserFactory` |
  | `App\Models\User` | `PnShop\Customer\Models\User`; `App\Models\User` extends it |
  | views `app`, `invoices.show` | `pnshop::app`, `pnshop::invoices.show` |
  | `packages/storefront-sdk` | `storefront-sdk/` in the package |

- **Customer model:** create and query customers through `User::modelClass()`, so the shop's configured model is used. The morph alias stays `customer`.
- **Modules:** the module list is `PnShop::MODULES` in the package. Add your own module providers with `extra_modules` in `config/pnshop.php`.
- **Routes:** the storefront's routes load from the package. The shop's `routes/web.php` is for its own routes, which load before the CMS page fallback.
- **Static analysis:** the storefront controllers are now core code and pass Larastan level 7.
- **Builds:**
  - Vite builds with the package as its root, so entries and manifest keys stay `resources/js/app.tsx`, and 1.0 theme bundles keep working.
  - `npm run build:core` writes the prebuilt storefront that releases ship.
- **Release trees:** `scripts/release/build-dist.sh <dir>` builds the package (with `theme/dist`) and the skeleton from a commit. See [publishing](../release/publishing.md).
