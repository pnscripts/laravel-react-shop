# Upgrade notes: Phase 6 (orders, payments, shipping, tax)

## Required actions

1. `php artisan migrate`. All changes keep existing data.
   - **Class moves:** orders and payment methods are stored under the morph aliases `order` and `payment_method`, and activity log and stock movement rows are rewritten.
   - **Order states:** orders get a `number` (`ORD-000042`), `status`, `payment_status`, `fulfillment_status` and `locale`, plus an `order_history` table. The old `order_statuses` list and `orders.order_status_id` are replaced:

     | Old status | Status | Payment | Fulfillment |
     |---|---|---|---|
     | pending | pending | unpaid | unfulfilled |
     | paid | processing | paid | unfulfilled |
     | shipped | processing | **unpaid** | fulfilled |
     | cancelled | cancelled | unpaid | unfulfilled |

     The old list did not say whether shipped orders were paid. Check them and record payments in the admin.
   - **Payments:**
     - `payment_methods.type` is renamed `gateway`, and a `cod` value becomes `cash_on_delivery`;
     - payment methods get `settings`, `position`, `min_total`, `max_total` and `countries`, plus a translations table;
     - new `payments` and `payment_transactions` tables, with one payment per existing order that matches its payment state.
   - **Shipping:**
     - new `shipping_zones`, `shipping_methods` (+ translations), `shipments` and `shipment_lines` tables;
     - orders get `shipping_method_id` and `shipping_method_name`;
     - order lines get `quantity_fulfilled`, which is set to the full quantity for orders whose stock was already taken.
   - **Tax:**
     - new `tax_classes`, `tax_zones` and `tax_rates` tables;
     - products and shipping methods get `tax_class_id`;
     - order lines get `tax_amount`.
   - **Refunds:** new `refunds` and `refund_lines` tables; order lines get `quantity_refunded` and `quantity_cancelled`.
   - **Invoices:** new `invoices` and `number_sequences` tables.
2. Fill in the bank details for bank transfer under Admin → Store → Payment methods.
3. Set up shipping zones and methods (Admin → Store), or run `php artisan db:seed --class=ShippingSeeder` for a starting point: standard delivery, free delivery from 100 and pickup. Until a method exists, checkout doesn't ask for delivery.
4. To charge tax:
   - run `php artisan db:seed --class=TaxSeeder` (classes Standard, Reduced and Zero rate), or create the classes yourself;
   - add a tax zone with rates;
   - check Admin → Settings → Tax: prices include tax by default, and set the store country.

   Until rates exist, nothing is taxed.
5. `npm run build`.

   - **Totals fix:** orders whose totals were filled by an earlier version of the Phase 5 backfill are corrected (`2026_10_05_150000`). That backfill ignored a stored sale price above the regular price, although that was the price charged. Their import payment rows are corrected with them.

## Behaviour changes

- **Order states:** orders have three independent states with fixed transitions, and the admin offers only the allowed next steps (see [orders](../ecommerce/orders.md)). The editable status list is gone.
- **Shipping and stock:** stock leaves the shelf when the fulfillment is set to *Shipped*. Before, this happened when the status was named "shipped".
- **Payment:** recording a payment on a pending order moves it to *Processing*.
- **History:** every change and note is kept in the order history, with the staff member or customer who made it.
- **Order numbers:** customers see order numbers instead of database ids. Configure them in Admin → Settings → Orders.
- **Payment methods:** methods are managed in the admin and offered by their rules (amount, country). Checkout refuses a method that doesn't apply to the order.
- **Payment instructions:** the order page shows them while payment is pending (bank details for bank transfer).
- **Delivery:** once shipping methods exist, checkout asks for a delivery option for the address and adds its price to the total.
- **Shipments:** orders can be shipped in parts from the admin, with tracking numbers that customers see. Stock leaves the shelf per shipped line.
- **Invoices:** paid orders get a numbered invoice by default (configurable). Set the legal name, VAT number and footer in Admin → Settings → Orders.
- **Refunds:** paid orders can be refunded per line or by amount from the admin, with optional restocking of returned items.
- **Tax:** once rates exist, the cart, checkout, orders and the admin show the tax per rate (included in the price, or added to it).
- **Payment methods whose `type` isn't a built-in gateway** (`cash_on_delivery`, `bank_transfer`) stay in the database but are not offered until a gateway with that code is installed.

## For developers

- **Class moves:**
  - `App\Models\{Order, OrderItem, OrderAddress}` → `PnShop\Sales\Models\…`
  - `App\Models\PaymentMethod` → `PnShop\Payment\Models\PaymentMethod`
  - `App\Services\CheckoutService` → `PnShop\Sales\Checkout\CheckoutService`
  - `App\Services\ShoppingCartService`, `App\DTOs\CartItemDTO`, `App\Exceptions\CartException` → `PnShop\Cart\…`
  - `App\Exceptions\CheckoutException` → `PnShop\Sales\Exceptions\CheckoutException`
- **Removed:** `App\Models\OrderStatus`, `OrderStatusSeeder` and `App\Services\OrderStatusService`.
- **Changing orders:**
  - change states with `PnShop\Sales\OrderWorkflow::transition($order, PaymentStatus::Paid, $actor, $note)`;
  - add notes with `addNote()`;
  - a transition that isn't allowed throws `InvalidOrderTransition`, an `OrderException`;
  - never write the state columns directly.
- **Payments:** gateways implement `PnShop\Payment\Contracts\PaymentGateway` and register with `PaymentGatewayManager`. See [payments](../ecommerce/payments.md).
- **`OrderStateChanged`** now also carries the `actor`.
- **Shipping:** carriers implement `PnShop\Shipping\Contracts\ShippingCarrier` and register with `ShippingCarrierManager`. See [shipping](../ecommerce/shipping.md).
- **`CartItemDTO`** now carries `weight` (grams) and `taxClassId`.
- **`CartTotals`** has a `meta` array for details stages hand on (the `TaxResult` is under `tax`).
- **Tax:** the calculation is the replaceable `PnShop\Tax\Contracts\TaxProvider`. See [tax](../ecommerce/tax.md).
- **`ShoppingCartService::toArray()`** accepts a totals context.
- **Events:**
  - `PnShop\Sales\Events\OrderPlaced` fires after checkout commits;
  - `OrderStateChanged` fires after each committed transition.
