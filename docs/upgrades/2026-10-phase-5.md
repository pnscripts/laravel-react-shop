# Upgrade notes: Phase 5 (customers, cart and checkout)

## Required actions

1. `php artisan migrate`. All changes keep existing data:
   - **Customers:** new `customer_groups` table with a default *Retail* group; `users` get `customer_group_id` and `phone`; new `customer_addresses` table (address books).
   - **Carts:** new `carts` and `cart_lines` tables.
   - **Orders:**
     - new `order_addresses` table (shipping and billing copies);
     - `orders.address` becomes nullable and is kept for orders placed before this upgrade, because free text cannot be split into address fields reliably;
     - new `subtotal`, `total` and `totals` columns, filled for existing orders from their lines;
     - new `stock_status` column: existing orders count as `fulfilled` (their stock was already taken), or `released` when cancelled.
2. Run the scheduler (`php artisan schedule:work`, or cron `* * * * * php artisan schedule:run`). It runs `pnshop:carts:prune` daily.
3. `npm run build`.

## Behaviour changes

- **Carts:**
  - They live in the database, not the session.
  - A guest's cart survives the browser session for 30 days (cookie `pnshop_cart`).
  - A signed-in customer's cart follows the account across devices.
  - Signing in merges the guest cart into the account cart.
  - Carts kept in the session before the upgrade are moved over on the next visit.
- **Checkout:**
  - It asks for a structured shipping address (country, city, postcode, …), and the phone number is required.
  - Billing is the same as shipping unless the customer unticks the box.
  - Signed-in customers pick a saved address or save a new one.
- **Stock:**
  - Placing an order **reserves** stock. It leaves the shelf (on hand) when the order is set to *shipped* (or *delivered* / *completed*).
  - Cancelling releases a reservation, or puts shipped stock back.
  - Available stock is on hand minus reserved, so what customers can buy is unchanged.
- **Spam protection:** checkout and registration refuse submissions that fill a hidden honeypot field, or that arrive less than 2 seconds after the form was shown (`PNSHOP_BOT_TRAP_MIN_SECONDS`).
- **Totals:** cart, checkout, order pages and the admin show a subtotal and total. Lines added by the `cart.totals` pipeline (shipping, discounts, tax; Phase 6) appear between them.

## For developers

- Checkout requests changed. Instead of `name`, `phone` and `address`, send:
  - `shipping[first_name|last_name|company|line1|line2|city|postcode|region|country_code|phone]`;
  - `billing_same_as_shipping`;
  - `billing[...]`;
  - `save_address`;
  - the bot-trap fields `contact_website` and `form_started`, from the page's `botTrap` prop.
- `ShoppingCartService` keeps its API; `totals()` returns the `CartTotals` breakdown, and `toArray()` adds `totals`.
- Change order statuses only through `App\Services\OrderStatusService`. It moves stock between reserved, fulfilled and released.
- New inventory methods are `reserve()`, `release()` and `commit()`. A new movement reason, `order_fulfilled`, is recorded when an order ships.
- Tests can use `TestCase::checkoutData($paymentMethodId, $overrides)` for a valid checkout submission.
